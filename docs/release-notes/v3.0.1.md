**v3.0.1: long actions no longer time out through https://gc.asaplabs.net.**
Cloudflare cuts off any page request that takes more than 100 seconds, and
shows an "error 524" instead. Three actions could take longer than that, so
through gc.asaplabs.net they always failed. They now start at once, show
their progress, and finish in the background:

- **Import v1 history, Dry run** (Hub admin). It used to fail every time on a
  real processed folder. The panel now shows progress ("Reading CDFs and
  matching them to the CSV: 500 of 12000") and then the same summary as
  before. **Stop** now works on a dry run too. A dry run still writes
  nothing, and like the loader and the real import, only one of these can run
  at a time.
- **Download diagnostics** (Hub admin). The bundle is built in the
  background with its progress shown, and the download starts on its own
  when it is ready. If the disk is too full, the panel says so when the build
  stops, not before it starts.
- **Export to PC with two or more queued reports** (the ZIP of analysis
  reports). Each PDF takes a few seconds, so a queue of about 30 or more ran
  past the limit. The button now counts the reports as they are made
  ("Generating 12/40…"), and the ZIP downloads when it is ready. Only the
  person who asked for a ZIP can download it. It can be downloaded once,
  within 10 minutes.

Nothing else changes: every result, report, CSV and export is exactly what
v3.0.0 produced.
