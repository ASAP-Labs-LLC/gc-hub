## Live updates

The main page and the Instruments page now update themselves. Nothing needs a
page refresh any more:

- **New samples appear in the list as the GC PCs send them.** When a sample
  is processed, held, fails, is reprocessed, is exported to the results CSV
  or is uploaded to QBench, its row changes in place. The list keeps its
  scroll position and your selection.
- **The Refresh button and its Ctrl+R shortcut are gone.** Ctrl+R now just
  reloads the page, as in any browser.
- **The notification bell updates when a notification arrives,** not on a
  30-second timer.
- **The Re-process progress box follows the samples as they finish,**
  instead of asking the hub every 1.5 seconds.
- **On the Instruments page, an agent's status updates at each heartbeat.**
  "Last seen" counts up on screen ("12 s ago").
- **A small "Live · updated just now" line sits at the bottom left** of the
  main page. It changes to "Reconnecting… · last update 40 s ago" when the
  page can't reach the hub, and catches up on its own when the hub is back.
- **After the hub is updated, an open page says so:** "Updated to vX —
  reload to use it", with a Reload button. It never reloads by itself, so
  nothing you are in the middle of is lost.

The page asks the hub what changed every 3 seconds while the tab is visible,
and every 30 seconds while it's hidden. The hub answers from memory, so an
open tab doesn't slow processing. An open tab also doesn't count as someone
using the hub, including the rows it fetches after a change: the 3 AM
restart and the updater's idle deploy still happen with the page left open,
and a tab left open doesn't keep its sign-in alive.

After a hub restart or update, an open page reloads its list on its own.

Nothing about how results are calculated, recorded, exported or displayed
has changed.

For admins and developers: the new `GET /api/live?since=<cursor>` endpoint
(needs a signed-in session), `live.py` (the in-memory event ring) and
`static/js/live.js` (`window.GCLive`). `/api/files` also accepts
`ids=1,2,3`, which returns just those samples. A GET sent with the header
`X-GC-Background: 1` (what `GCLive.bgFetch` sends) is not counted as
activity.
