**v8.1.0: pick the run a comparison standard comes from, tag its GC as you add it, and a report with no comparison.**

## Upgrading from v8.0.1

- Install as usual with Admin · Server > "Restart & install v8.1.0". No database change; rolling back is safe.
- Nothing about existing results, the results CSV or the comparison reports changes. Reports compared with a standard print exactly as in v8.0.1.

## New

- **Add a standard from a particular run.** In Settings > Comparison standards, "Lab ID of the run" also takes the label the Samples list shows for a re-run, such as `DIESEL STD (30)`, and adds that run. When a lab ID has more than one run and you don't name one, pressing **Add standard** opens a **Run** list under the form (for example "DIESEL STD (30) · GC-1 · Oct 3 10:15 · Final"). Pick one and press **Add this run**. The newest final run is selected to start with. The message says which run was used.
- **The GC is set when you add a standard.** The add form has a **GC** list. "GC of the run" (the default) tags the new standard with the GC the run was made on, so there is nothing left to tag afterwards. You can pick another GC, or "Not tagged". Adding a standard under a name that already exists replaces its file and sets its GC again.
- **Export a report with no comparison.** In Export report (and Add to queue), "Compared with" has a last choice, **No comparison (chromatogram only)**. The PDF is one page: the sample's chromatogram as Overview draws it, with its own carbon numbers along the top, up to the "Show up to" limit, then its marked regions and notes. There are no findings, conclusion, ranges or other standards. It works for Download PDF, the report queue, Download all and Upload to QBench. The queue lists it as "No comparison". The report log records it with no standard. Compare itself still needs a standard.

## For other programs

- `GET /api/lab/<lab_id>`: each run also has `run_no` and `display_name`, the Samples list's "(N)" label (counted per GC and exact lab ID, oldest first).
- `POST /api/comparison-standard` takes an optional `instrument_id`:
  - left out: the run's own GC;
  - an instrument id: that GC (unknown → 404, nothing added);
  - `null`: not tagged.

  The answer includes the new `standard` row.
- Report requests (direct, ZIP, QBench queue items) take `no_comparison: true`. The standard, ranges, other standards and conclusion are then ignored. `/api/analysis` still requires `standard_name`.
