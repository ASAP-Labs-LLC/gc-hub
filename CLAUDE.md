# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Flask backend + single-page frontend that is a **1:1 web clone of the PyQt5 desktop "GC Viewer & Distillation Parser"** (documented in the `gc-data` repo, which this repo was extracted from). It watches a folder for gas-chromatograph `.CDF` files, runs an ASTM D2887 simulated distillation, derives ASTM D86 temperatures, serves Plotly traces + a live results table, and can attach generated PDF reports to QBench samples. The REST API in `app.py` delegates all heavy lifting to the backend modules (`distill`, `looker`, `settings`, `qbench_pdf_uploader`).

## Deployment topology (important, not obvious from the code)

- **Production is moving to ASAPSV1 under the COA Reviewer updater** (phase 1): a `v*` tag builds a release, the updater installs it into `C:\ASAPApps\gc\releases\<tag>\`, health-checks it and runs it on port 5560 with state in `C:\ASAPApps\gc\data\`. See *Deployment* below, `RELEASING.md` and `DEPLOY.md`.
- **The copies on the share are legacy until phase 2.** The GC workstations still run the app from `\\ASAPServer\Labsharedrive`, launched by `run.pyw` (a `pystray` tray app using `ctypes.windll`, `taskkill`, `CREATE_NEW_CONSOLE`), which auto-restarts the Flask subprocess when a `.py` changes (watchdog). They do **not** receive releases; a fix reaches them only if the files are copied onto the share by hand (with Ryan's approval). Legacy mode (no `GC_DATA_DIR`) exists so they keep working unchanged.
- **Development is on a Mac**, in this git checkout (`~/Projects/gc-hub`). Do not edit the share copies to ship a change; tag a release.
- **Windows-isms are intentional, not bugs:** `chromedriver.exe`, UNC credential paths (`\\ASAPServer\...\qbenchlogin.txt`), `os.environ["TEMP"]`, `run.pyw`'s win32 calls, `taskkill`/`CREATE_NEW_PROCESS_GROUP` in the restart code. Don't "port" them to POSIX.
- **History:** the share folder this code came from is `GC 2026.5 2887 Advanced analysis/`. (An earlier copy of this file claimed `GC 2026.5 WEB/`; that tree stopped at 2026-06-16, has never been launched, and lacks `analysis_core.py`, `fuel_fit.py` and `sample_flags.py`.) `GC 2027/webapp` is the same 2026-06-16 build with D7096 *gasoline* modules bolted on — it is the gasoline fork, not newer diesel work.

## Run / develop

```bash
# from the repo root
pip install -r requirements.txt -r requirements-dev.txt   # Python 3.12+ (numpy/scipy pins require it)
python app.py                          # legacy mode on http://0.0.0.0:5560, debugger off
python app.py --dev                    # Flask debug mode (interactive debugger: never in production)
python app.py --port 5561              # or GC_PORT=5561 python app.py
GC_DATA_DIR=/tmp/gcdata PORT=5570 python app.py   # deployed mode, as the updater runs it
```
`app.py` accepts `--port`, `--dev` and `--no-tray` (ignored; the updater's `health_args`). Any other flag is an error, and prefixes are not expanded (`--d` is not `--dev`). In legacy mode the first launch creates `~/.gc_viewer_settings.json`; configure paths via the in-app Settings, not by hand. On the share's Windows machines the entry point is double-clicking `run.pyw` (tray icon → Restart / Open in Browser).

## Deployment

- **Two modes, decided by `GC_DATA_DIR`** (`paths.py`). **Deployed** (set by the updater to `C:\ASAPApps\gc\data`): every piece of state lives under that folder (`settings.json`, `distill_results.csv`, `processed_cdf/`, `exports/`, `gc_comparison_standards/`, `dircache.json`, `notifications.json`, rotating `app.log`), `PORT` wins over every other port source, there is no pidfile, and a restart only **exits** so the updater relaunches it (except while the updater is `paused`). **Legacy** (unset): the historic home-folder and cwd-relative locations, per-port settings files, pidfile, and self-respawn. An explicit settings value always wins; `paths.py` changes only defaults and the settings file location.
- **`GET /healthz`** is the updater's contract: HTTP 200 with `{status: "ok", version, pid, active_sessions, idle_seconds}`. `version` is the `VERSION` file (`version.py`; `"dev"` in a checkout), and must equal the release tag. No auth, no outbound calls, and polling it does not count as activity. The health check boots the app with an **empty** `GC_DATA_DIR`, so startup must succeed unconfigured (no watch folder → no Looker, logged; no QBench credentials → fine until used). `tests/test_healthz.py` boots it exactly that way.
- **Restart installs a staged update.** `POST /api/restart` asks `restart_policy.decide()` whether the updater has a newer healthy release staged; if so it writes `switch-requested` and waits for the updater's `switch-accepted`/`switch-refused` (`restart_update.py`, the handshake), falling back to a plain restart. The Settings button reads "Restart & install vX.Y.Z" when a release is staged.
- **Never edit a release folder** on the server; releases are immutable. Ship by tagging: `git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z` (commit pushed first). `.github/workflows/release.yml` runs `.github/workflows/ci.yml` (also on every push: both suites on Python 3.12 and 3.14 with `GC_REQUIRE_DEPS=1`, identity checks against coa-reviewer's latest release, an advisory Windows install + boot), then a separate write-token job runs `scripts/package_release.sh`, the single source of truth for the zip's contents (tracked source only; state excluded by name; `VERSION` stamped from the tag; tags must be `vX.Y.Z[-pre]`; a tag containing `-` is published as a prerelease, which the updater never stages; `docs/release-notes/<tag>.md`, when present, heads the release notes). Anything that changes how results are calculated, recorded or displayed is a MAJOR bump. See `RELEASING.md`; first-time server setup is in `DEPLOY.md`.
- **`requirements.txt` pins everything with `==`**, transitive deps included (frozen from a Python 3.14 venv; platform-only packages carry markers). The updater builds each release's venv from it with its own Python on Windows, recorded as CPython 3.14.4; see `RELEASING.md` "Dependency pins".
- **`supervisor.py` and `restart_update.py` are byte-identical copies of coa-reviewer's** (the updater imports whichever app's copy it finds first). Never edit them here; change them in coa-reviewer and copy. `tests/test_restart_update.py` checks when `../coa-reviewer` exists (CI clones its latest release there).

## Running more than one instance (legacy mode only)

This applies to the share copies. Under the updater there is one instance, one data dir and one port. Several copies can run on one machine — one per GC workstation folder. Double-clicking `run.pyw` opens a port dialog (default 5560, dropdown of previously used ports) before the server starts; it refuses a port that is already bound. Pass `--port N` or set `GC_PORT` to skip the dialog for an auto-started instance.

`instance.py` derives everything that must differ from the port alone:

| | port 5560 | port 5561 |
|---|---|---|
| Settings | `~/.gc_viewer_settings.json` | `~/.gc_viewer_settings-5561.json` |
| Pidfile | `.gc_server.pid` | `.gc_server-5561.pid` |

Port 5560 keeps the historic filenames, so the existing install needed no migration. Remembered ports live in `~/.gc_launcher_ports.json` (shared by all instances — it is a list of choices, not config).

A new instance's settings are seeded from the 5560 file, **except** `settings.PER_INSTANCE_KEYS` (`watch_dir`, `processed_cdf_dir`, `distill_output`, `export_folder`), which reset to defaults so the operator must choose them. Two instances sharing `distill_output` would both append to one results CSV, and a shared `export_folder` mixes two workstations' reports together.

**Give each instance its own watch folder.** The Looker dedupes on `(Lab ID, InjectionDateTime)` within one CSV, not across instances, so two instances watching one folder both process every file.

## Architecture

- **`app.py`** — the Flask app and all its routes. `_init_app()` starts daemon threads: a Looker file-watcher and the 3 AM auto-restart loop. It runs on import when `app` is imported, and under `__main__` after the port guard (`supervisor.wait_until_free`; a second bind to a served port succeeds silently on Windows) and the startup tidy-up of switch files and results-CSV temp files. **Importing `app` therefore has side effects** — tests assert the route surface via AST instead of importing it. Long-running work (scans, QBench uploads) runs in background threads and streams progress to the frontend over **Server-Sent Events** (`/api/*/stream`); `_publish*/_sse_stream` fan messages out to subscriber queues. The QBench upload queue is append-while-running and supports mid-run credential re-prompt and per-item skip.
- **`distill.py`** — the numeric core. `_cumulative_percent` (trapezoidal integration → 0–100%), `_interp_bp` (boiling-point interpolation at `PERCENT_LEVELS`), `_convert_to_d86` (ASTM D86 App. X4 polynomial via `_CONVERSION_COEFF`/`_CONVERSION_REL`), `_append_csv_row` (appends; `process_cdf` skips a row whose `Lab ID` + `InjectionDateTime` already exists), and `_atomic_write_csv` (every whole-file rewrite of the results CSV: temp file + fsync + `os.replace`, retried on Windows sharing locks). All CSV and NetCDF access is serialized through module locks (`_CSV_LOCK`, `_NETCDF_LOCK`). `calibration_ladder(conf)` is the one place retention times are paired with carbon numbers for labelling ranges (the Analysis tab, report export, the analysis PDF and the QBench upload all call it): it uses the operator's saved peak→carbon assignments for the active calibration CDF, the same source as the distillation math, so ignored peaks (CS₂, impurities) never get a carbon, and keeps the longest run of carbons increasing with time; it falls back to sequential auto-detection only when fewer than two assignments are usable. `analysis_core` rejects `times`/`carbons` of different lengths at its boundary. `CSV_HEADER` is 31 columns (D2887 + D86 cuts + `Best Fit`/`Fit Score`). **Approximation only — not ASTM-certified.**
- **Cross-site write guard** (`app._refuse_cross_site_writes`, a `before_request`): a state-changing (`POST/PUT/PATCH/DELETE`) `/api/` request whose `Sec-Fetch-Site` is not `same-origin`/`none`, or whose `Origin` does not match the host, gets 403. There is no login, and the app listens on the lab LAN, so this is what stops any page open in a lab browser from posting here. Requests with neither header (curl, the updater, tests) pass. DNS rebinding is not covered. Admin-gated routes additionally require `Content-Type: application/json` (`_admin_json_body`) and the admin password (`_check_admin` → `admin_auth`, below). Agents send no `Origin`, so the guard never blocks them.
- **`admin_auth.py`** (2B1, D13) — the admin password: salted PBKDF2-HMAC-SHA256 (310k iterations, per-install salt) in the store's `settings_kv["admin_password"]`, checked with `hmac.compare_digest`, with an in-memory per-client backoff after 5 failures. **There is no default password**: until one is set at `/admin/setup` (first use only; `POST /api/admin/setup`), every admin action is refused with a message pointing there. Change it with `POST /api/admin/password {password, new_password}`. Blueprint registered in `app.py`; its `after_app_request` hook gives an admin route's 403 the real reason (not set up / throttled). A forgotten password is reset by deleting that `settings_kv` row on the server.
- **`ingest_api.py`** (2B1) — the hub side of contract §1 (Blueprint): `POST /api/ingest` (bearer token checked first, 25 MB cap before reading, sha/mtime headers, → `pipeline.submit`; 201/200/202/409/400/401/403/413/415), `POST /api/agent/heartbeat` (upserts `agents`, delivers a pending command once), `GET /api/agent/results` (the `export_rows` ledger), `GET /api/agent/package[.zip]` (built from `agent/` by `agent/build_package.py`, cached per version). Tokens: only the sha256 is stored (`instruments.token_hash`); `POST /api/admin/instruments/<id>/installer` (admin) mints one (a second needs `confirm_revoke: true` and revokes the first) and returns the installer zip; `POST /api/admin/hub-url` overrides the URL written into it (default: the request's host). `POST /api/admin/instruments/<id>/agent-command`, `GET /api/agents` (status + clock skew). Agent paths are in `_NON_ACTIVITY_PATHS`.
- **QBench API credentials** — `qbench_secrets.py` resolves the client id/secret at use time (`QBENCH_CLIENT_ID`/`QBENCH_CLIENT_SECRET` env → the JSON store at `QBENCH_STORE_PATH` or `%APPDATA%\ASAPLabs\qbench.json` → `QBenchSecretMissing`); `qbench_client.py` no longer reads them at import, so the app boots without them. Settings > QBench API (`GET/POST /api/qbench-api-credentials`, admin-gated) test-authenticates a submitted pair with one bounded token request and only then writes it with `qbench_secrets.save_default()` (atomic, keeps other `profiles`). The secret is never returned. This is separate from the Selenium web login (`/api/qbench-credentials`, `qbenchlogin.txt`).
- **`paths.py`** — where every piece of runtime state lives, legacy vs deployed (see *Deployment*). Stdlib-only, no import-time side effects, every function takes `env` for tests. Settings, notifications and the defaults in `settings.DEFAULTS` all come from here.
- **`version.py`** — `APP_VERSION` from the first line of `VERSION` next to the code, `"dev"` when absent. Shown in the bottom-right badge on every page and reported by `/healthz`.
- **`restart_policy.py`** — how the process may restart itself: exit-only under the updater (spawn only while it is `paused`), spawn-then-exit in legacy mode, never while `switching`/`switch-accepted` exists; the once-a-day auto-restart storm guard and minimum uptimes; `decide()` / `await_switch()` for the restart→switch handshake. Stdlib + `restart_update` only, so it is unit-tested without importing app.
- **`looker.py`** — `Looker` thread that polls `watch_dir` for new `.CDF`, copies/renames into the processed dir, and calls `distill.process_cdf()`; dedupes on `(Lab ID, InjectionDateTime)`.
- **`instance.py`** — per-instance identity, so several copies can run at once. Owns port resolution (deployed: `PORT` wins; then `--port` → `GC_PORT` → 5560; a stray `PORT` is ignored in legacy mode), validation, the port-in-use probe, and the per-port settings/pidfile paths. Stdlib-only and side-effect-free at import, which is what lets it be unit-tested and imported by both `app.py` and `run.pyw`.
- **`settings.py`** — JSON config at `paths.settings_file()`: `GC_DATA_DIR/settings.json` when deployed, else `~/.gc_viewer_settings.json` (or `~/.gc_viewer_settings-<port>.json` off the default port — see *Running more than one instance*). `DEFAULTS` is the source of truth for keys; `load_settings()` merges the file over defaults and ensures the comparison-standards dir exists. `PER_INSTANCE_KEYS` are the paths a second instance must not inherit.
- **`qbench_pdf_uploader.py`** — headless-Chrome Selenium upload of a PDF to a QBench sample. `attach_pdf_to_sample()` does: API lookup (lab_id → sample_id) → login (raising `LoginFailedError` on bad creds/lockout) → attach → save → verify. `app.py` catches `LoginFailedError`, so keep it.
- **`qbench_client.py`** — thin QBench REST v2 client (JWT auth, rate limiting, retries). **Must stay vendored in this repo.**
- **`analysis_core.py`** — Analysis-tab numerics, importable without app.py's side effects. Two deviation channels: the rolling low-quantile *trend* difference (broad envelope deviations) and a *spike* channel on the raw sample−standard difference with a min-width guard (`analysis_spike_min_width_min`, default 0.02 min) — the trend's low quantile erases short tall spikes (gasoline adulteration) by construction, so never remove the spike channel. Also owns `resolve_report_ranges` (request ranges → saved `analysis_range_overlays` → legacy gas/oil) used by `/api/analysis` and both report-export routes via `_run_export_analysis`.
- **`sample_flags.py`** — operator-defined flag rules (JSON in `sample_flag_rules` setting): `{name, above|below, threshold, t_start, t_end, color, enabled}`. `above` = any point in window exceeds; `below` = all points stay under (no-signal case). Legacy `early_signal_*` settings auto-migrate. app.py caches per-file results keyed on a rules fingerprint (`.sample_flags_cache.json`); file entries expose `flags` + legacy `early_signal` bool.
- **`fuel_fit.py`** — fuel-type best-fit vs the comparison standards: baseline-subtracted, area-normalized envelopes (amplitude-invariant), small retention-shift search, cosine score; NNLS blend names two-component mixes (`Mix: A + B (80/20)`), else `Mix`. Tunables in settings (`bestfit_*`). Called from `distill.process_cdf` (CSV columns `Best Fit`/`Fit Score`), the `/api/best-fit` route, and file-list enrichment (`.bestfit_cache.json`). CDF reading is injected (`load_standards(dir, reader)`) to avoid import cycles.
- **Frontend pure-logic modules** (window globals + module.exports, node-tested via `node tests/js/run.js`): `selection.js`, `report_payload.js` (export payloads carry the operator's region overlays), `flagrules.js` (rule editor rows ↔ rules, legacy migration mirror), `restart.js` (Restart button label/confirm text from the staged-update decision), `qbench_api.js` (the QBench API credential status line).

## QBench gotcha (caused a production outage)

`qbench_pdf_uploader._api_lookup` does `from qbench_client import QBenchAPIClient`. It must resolve the **local** `qbench_client.py` (on `sys.path` because `app.py` is run from its own folder, by `run.pyw` on the share and with `cwd=current` by the updater). Do **not** reintroduce any `sys.path.insert` to an external share path (the old `…\COA Reviewer\V2\Past Data Manager\API`) — that dir is gone and importing from it took uploads down. `tests/test_qbench_import.py` guards this.
