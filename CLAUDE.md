# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The **GC hub** (v2): one Flask process on ASAPSV1 that receives gas-chromatograph `.CDF` files (from the GC-PC agents over HTTP, or an admin folder load), stores them and their results in SQLite, runs an ASTM D2887 simulated distillation and derives ASTM D86 temperatures per instrument, appends each final result to the instrument's results CSV (the file LEM tails), serves Plotly traces and the results table, and can attach generated PDF reports to QBench samples. It began as a 1:1 web clone of the PyQt5 desktop "GC Viewer & Distillation Parser" (documented in the `gc-data` repo); the UI still looks like it (the redesign is phase 5). Phase 2 design: `docs/superpowers/specs/2026-09-28-phase2-multi-instrument-hub-design.md`.

## Deployment topology (important, not obvious from the code)

- **Production is ASAPSV1 under the COA Reviewer updater**: a `v*` tag builds a release, the updater installs it into `C:\ASAPApps\gc\releases\<tag>\`, health-checks it and runs it on port 5560 with all state in `C:\ASAPApps\gc\data\` (`GC_DATA_DIR`). See *Deployment* below, `RELEASING.md` and `DEPLOY.md`.
- **v2 is hub mode only (spec D14).** `app.py` refuses to start without `GC_DATA_DIR`; `run.pyw`, `looker.py`, the watch-folder scanner and the per-port instances are gone. The copies on `\\ASAPServer\Labsharedrive` (launched by `run.pyw` on the GC workstations) keep running **v1.x** until each GC PC is cut over to the agent. Share fixes come from branch **`maint/v1`** (cut at v1.1.0) and are hand-copied per DEPLOY.md; they are **never published as GitHub releases** (the updater follows "latest", so a later v1.x release would downgrade ASAPSV1; a v1.x tag only with `make_latest=false`).
- **Development is on a Mac**, in this git checkout (`~/Projects/gc-hub`). Do not edit the share copies to ship a change; tag a release.
- **Windows-isms are intentional, not bugs:** `chromedriver.exe`, UNC credential paths (`\\ASAPServer\...\qbenchlogin.txt`), `os.environ["TEMP"]`, `msvcrt` locks in `exports.py`, `taskkill`/`CREATE_NEW_PROCESS_GROUP` in the restart code. Don't "port" them to POSIX.
- **History:** the share folder this code came from is `GC 2026.5 2887 Advanced analysis/`. `GC 2027/webapp` is the 2026-06-16 build with D7096 *gasoline* modules bolted on (the gasoline fork, not newer diesel work).

## Run / develop

```bash
# from the repo root
pip install -r requirements.txt -r requirements-dev.txt   # Python 3.12+ (numpy/scipy pins require it)
GC_DATA_DIR=/tmp/gcdata python app.py              # http://0.0.0.0:5560, debugger off
GC_DATA_DIR=/tmp/gcdata python app.py --dev        # Flask debug mode (interactive debugger: never in production)
GC_DATA_DIR=/tmp/gcdata PORT=5570 python app.py    # as the updater runs it (PORT wins; else --port, GC_PORT, 5560)
```
Without `GC_DATA_DIR` the app exits with code 2 and a message pointing to DEPLOY.md. `app.py` accepts `--port`, `--dev` and `--no-tray` (ignored; the updater's `health_args`). Any other flag is an error, and prefixes are not expanded (`--d` is not `--dev`). The first start in a data folder creates `gc.db`, the `gc1` instrument (from `settings.json`), gc1's corrections (seeded once from `correction_factors_json`) and `admin-setup-code.txt`; set the admin password at `/admin/setup`. Server-side tools: `python tools/load_folder.py`, `python tools/parity_report.py`, `python tools/import_history.py` (dry run only); the parity runbook is in DEPLOY.md ("Parity check before cutover"): the loader runs on a **scratch** data folder with `--copy-instrument-from <production data>` (production's `gc.db` read-only; copies the instrument's calibration CDF + assignments, method map, `live_since` and hub corrections, plus `settings.json` and comparison standards, never the export path or token) and `--process`, which refuses only a folder a hub has served (`app.log` in it) unless `--hub-port` names that hub's port and nothing answers there.

## Deployment

- **Every piece of state lives under `GC_DATA_DIR`** (`paths.py`): `gc.db` (+ `backups/gc-<date>.db`, 14 kept), `cdf/<inst>/<YYYY>/<MM>/…` (raw CDFs, kept forever), `results/<inst>_results.csv` + `.gchub.json` sidecar (unless an instrument's `export_path` points at the share CSV LEM tails), `settings.json`, `exports/` (report PDFs), `gc_comparison_standards/`, `notifications.json`, `admin-setup-code.txt` (until setup), rotating `app.log`. `PORT` wins over every other port source, there is no pidfile, and a restart only **exits** so the updater relaunches it (except while the updater is `paused`, when it spawns its own replacement).
- **`GET /healthz`** is the updater's contract: HTTP 200 with `{status: "ok", version, pid, active_sessions, idle_seconds}`. `version` is the `VERSION` file (`version.py`; `"dev"` in a checkout), and must equal the release tag. No auth, no outbound calls, and polling it does not count as activity. The health check boots the app with an **empty** `GC_DATA_DIR`: the hub starts on a background thread (store, gc1, Worker, exporter) and `/healthz` answers at once; no calibration or corrections → samples would wait, which is fine. `tests/test_healthz.py` boots it exactly that way.
- **Restart installs a staged update.** `POST /api/restart` asks `restart_policy.decide()` whether the updater has a newer healthy release staged; if so it writes `switch-requested` and waits for the updater's `switch-accepted`/`switch-refused` (`restart_update.py`, the handshake), falling back to a plain restart. The Settings button reads "Restart & install vX.Y.Z" when a release is staged. The hub's threads are stopped right before the process exits (`_stop_hub`; when the updater accepts a switch, `on_taken=_stop_hub`), and started again if a self-respawn fails.
- **Never edit a release folder** on the server; releases are immutable. Ship by tagging: `git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z` (commit pushed first). `.github/workflows/release.yml` runs `.github/workflows/ci.yml` (also on every push: both suites on Python 3.12 and 3.14 with `GC_REQUIRE_DEPS=1`, identity checks against coa-reviewer's latest release, an advisory Windows install + boot), `exports-ci.yml` and `agent-ci.yml`, then a separate write-token job runs `scripts/package_release.sh`, the single source of truth for the zip's contents (tracked source only; state excluded by name; `VERSION` stamped from the tag; tags must be `vX.Y.Z[-pre]`; a tag containing `-` is published as a prerelease, which the updater never stages; `docs/release-notes/<tag>.md`, when present, heads the release notes). Anything that changes how results are calculated, recorded or displayed is a MAJOR bump. See `RELEASING.md`; first-time server setup is in `DEPLOY.md`.
- **`requirements.txt` pins everything with `==`**, transitive deps included (frozen from a Python 3.14 venv; platform-only packages carry markers). The hub does not use `pystray`/`watchdog` (the agent declares its own deps in `agent/requirements-agent.txt`). The updater builds each release's venv from it with its own Python on Windows, recorded as CPython 3.14.4; see `RELEASING.md` "Dependency pins".
- **`supervisor.py` and `restart_update.py` are byte-identical copies of coa-reviewer's** (the updater imports whichever app's copy it finds first). Never edit them here; change them in coa-reviewer and copy. `tests/test_restart_update.py` checks when `../coa-reviewer` exists (CI clones its latest release there).

## Architecture

- **`app.py`** — the Flask app and its routes; samples are addressed by `sample_id` and every route reads the store (route fates: `docs/superpowers/plans/2026-09-28-phase2-T4-routes.md`, pinned by `tests/test_route_fates.py`). It refuses to start without `GC_DATA_DIR`. `_init_app()` starts the hub on a background thread (`hub.start_with_retry(hub.start)`: 5 s doubling to 5 min, notified after 3 failures; then primes `sample_cache`) and the 3 AM auto-restart loop (idle = no requests, no QBench upload, no running admin job, no due Worker job); it runs on import, and under `__main__` after the port guard (`supervisor.wait_until_free`; a second bind to a served port succeeds silently on Windows) and the tidy-up of switch files. **Importing `app` therefore has side effects** — tests assert the route surface via AST instead of importing it. Reports, the dashboard numbers, `/api/table` and Export to LIMS read the **stored revision** and never recompute (`/api/table` shows the sample's corrected `injection_dt`, other cells as stored). `/api/settings` POST (JSON only) changes only `settings.OPERATOR_KEYS` (flag rules, series colours) and, with the admin password, `settings.ADMIN_KEYS` (`bestfit_*`, `analysis_*`); any other changed key is a 400 (paths, calibration, corrections, `blank_max_intensity_pa`), and the standards and export folders are fixed under the data folder. Comparison standards are added from a `sample_id` only; add/rename/delete are admin-gated. `POST /api/calibration` is admin-gated. There are no server-side desktop actions (`/api/browse`, `/api/open-folder` are gone). QBench uploads run in a background thread and stream progress over **Server-Sent Events** (`/api/qbench-upload/stream`); each PDF is built with `_build_report_pdf`, like the direct and ZIP exports. **`_report_content(sample, params, conf, db)` is the one analysis pass** behind `/api/analysis` and every export (`items`, `text`, `conclusion_generated`, `windows`, `params_used`, `comments`, …) and the PDF's only analysis input; `_report_request` takes the report fields from a body/queue item (a client `bullets` string is never read). The report HTML escapes every interpolated string and its footer prints the parameters, ranges and app version. Comments and `report_log` rows go through phase 4's `comments` module (guarded import; no comments/no log until it is present). The upload queue is append-while-running and supports mid-run credential re-prompt and per-item skip.
- **`hub.py`** — the one start-up (`hub.start(app_conf)` → `HubRuntime`; `running()`, `.stop()`, `.wake_exports()`; `start_with_retry`; `background_busy`): `store.migrate` → `instruments.bootstrap_gc1` → the one `pipeline.Worker` (notifier = the notification store, **store-only** hub corrections `hub.corrections_provider`, never the phase-1 file per job; `on_final` wakes the exporter and refreshes `sample_cache`) → `exports.HubExporter(notifier).start()` → outside the lock, `seed_gc1_corrections` (first start: gc1's 11 factors from the phase-1 file via `instrument_admin.seed_gc1`, notified; a missing/invalid file leaves gc1 `pending_corrections`, never zeros) → `Maintenance` (retries the gc1 seed every 10 minutes while unseeded; nightly `store.backup_nightly` once per local day from 1 AM, notified on failure and retried hourly; `store.jobs.prune_done` of jobs older than 30 days). Hands the exporter to `hub_admin`/`instruments_api` `set_exporter`.
- **`hub_admin.py`** — admin Blueprint (JSON + admin password on every call): `POST /api/admin/load-folder` runs `jobs.load_folder` as a background admin job (`AdminJobs`, one job of either kind at a time, polled with `POST /api/admin/jobs/status`, stopped with `/api/admin/jobs/stop`), the v1 history import `POST /api/admin/import-history/dry-run|start|last-run` (`jobs.import_history` on the same runner; the page's *Import v1 history* panel), `POST /api/admin/exports[/<id>/adopt|new-path|write-fresh]` on the running exporter (refusals are 409 `{error, reason}`), and the page `/admin/hub`.
- **Store and processing** — `store.py` (SQLite schema/migrations, short-lived connections, `BEGIN IMMEDIATE`, nightly `VACUUM INTO` backups), `pipeline.py` (`submit` dedupes by sha256 and stores the CDF; the durable `jobs` queue; the `Worker` and status machine: `received` → `final` | `awaiting_calibration` | `pending_corrections` | `other_method` | `review_method` | `error`; revisions; the "at or before" blank rule; `export_to_lims`, `release_backfill`, conflict Replace), `instruments.py` (`InstrumentContext`, calibration-usable rule, `bootstrap_gc1`, `startup`), `methods/` (method registry; `d2887.compute` wraps `distill.compute`), `corrections.py` (`StoreProvider` for hub-owned factors, `FileProvider`/`seed_from_file` for the phase-1 file; never a silent zero), `exports.py` (append-only per-instrument CSVs from the `export_rows` ledger, sidecar refusal rules, adopt/new path/write fresh), `import_match.py` (v1 CSV ↔ hub matcher), `jobs/import_history.py` (the 2D history import: v1 rows stored verbatim as revisions, every sample backfill, no export rows, nothing recomputed), `jobs/load_folder.py` + `tools/load_folder.py` + `tools/parity_report.py` (the folder loader, `copy_instrument` for scratch parity stores, and the v1 parity gate).
- **`distill.py`** — the numeric core. `compute(cdf, conf, blank_path)` returns one result row and writes nothing (the hub's `methods/d2887.py` wraps it); `_cumulative_percent` (trapezoidal integration → 0–100%), `_interp_bp` (boiling-point interpolation at `PERCENT_LEVELS`), `_convert_to_d86` (ASTM D86 App. X4 polynomial via `_CONVERSION_COEFF`/`_CONVERSION_REL`), `cdf_identity`/`cdf_lab_name` (lab ID and injection time, shared with the importer), `parse_injection_datetime` (the compact ChemStation stamp first). `process_cdf` (v1's move + CSV append) is kept only as the golden reference the tests compare `compute` with; the hub never calls it. NetCDF reads are serialized (`_NETCDF_LOCK`). `calibration_ladder(conf)` is the one place retention times are paired with carbon numbers for labelling ranges (the Analysis tab, report export, the analysis PDF and the QBench upload): it uses the saved peak→carbon assignments for the calibration CDF, the same source as the distillation math, so ignored peaks (CS₂, impurities) never get a carbon; the hub computes with auto-detection off (`allow_auto=False`: an unusable calibration holds samples as `awaiting_calibration`). `analysis_core` rejects `times`/`carbons` of different lengths at its boundary. `CSV_HEADER` is 31 columns (D2887 + D86 cuts + `Best Fit`/`Fit Score`). **Approximation only — not ASTM-certified.**
- **Cross-site write guard** (`app._refuse_cross_site_writes`, a `before_request`): a state-changing (`POST/PUT/PATCH/DELETE`) `/api/` request whose `Sec-Fetch-Site` is not `same-origin`/`none`, or whose `Origin` does not match the host, gets 403. There is no login, and the app listens on the lab LAN, so this is what stops any page open in a lab browser from posting here. Requests with neither header (curl, the updater, tests) pass. DNS rebinding is not covered. Admin-gated routes additionally require `Content-Type: application/json` (`_admin_json_body`) and the admin password (`_check_admin` → `admin_auth`, below). Agents send no `Origin`, so the guard never blocks them.
- **`admin_auth.py`** (2B1, D13) — the admin password: salted PBKDF2-HMAC-SHA256 (310k iterations, per-install salt) in the store's `settings_kv["admin_password"]`, checked with `hmac.compare_digest`, with in-memory throttling (attempts reserved before hashing: one in flight per client, backoff after 5 failures, a hub-wide failure budget, at most two PBKDF2 runs at once). **There is no default password**: until one is set at `/admin/setup` (first use only; `POST /api/admin/setup {password, setup_code}`), every admin action is refused with a message pointing there. The one-time setup code is in `GC_DATA_DIR/admin-setup-code.txt` and logged at WARNING in `app.log`; setup also refuses a foreign `Host` (DNS rebinding). Change it with `POST /api/admin/password {password, new_password}`. Blueprint registered in `app.py`; its `after_app_request` hook gives an admin route's 403 the real reason (not set up / throttled). Admin/setup/heartbeat JSON bodies are capped at 64 KiB (`limit_json_body`, also in `app._admin_json_body`). A forgotten password is reset by deleting that `settings_kv` row (DEPLOY.md); a new setup code then appears.
- **`ingest_api.py`** (2B1) — the hub side of contract §1 (Blueprint): `POST /api/ingest` (bearer token checked first, 25 MB cap before reading, sha/mtime headers, → `pipeline.submit`; 201/200/202/409/400/401/403/413/415), `POST /api/agent/heartbeat` (upserts `agents`, delivers a pending command once), `GET /api/agent/results` (the `export_rows` ledger), `GET /api/agent/package[.zip]` (built from `agent/` by `agent/build_package.py`, cached per version). Tokens: only the sha256 is stored (`instruments.token_hash`); `POST /api/admin/instruments/<id>/installer` (admin) mints one (a second needs `confirm_revoke: true` and revokes the first) and returns the installer zip; `POST /api/admin/hub-url` sets the URL written into it (without it, the request's host is used only if it is a non-loopback IP or one of the machine's names; else 409 `needs_hub_url`). `POST /api/admin/instruments/<id>/revoke-token`; a disabled instrument's token gets 403 on results/package and no commands. `POST /api/admin/instruments/<id>/agent-command`, `GET /api/agents` (status + clock skew). Agent paths are in `_NON_ACTIVITY_PATHS`.
- **Instruments page** (2A2) — `instruments_api.py` (Blueprint: `GET /instruments`, open `GET /api/instruments[/<id>[/calibration|/calibration-candidates|/corrections|/methods|/backfill]]`, `/api/conflicts`, `/api/standards`; every change is `POST /api/admin/...` with the admin password via `ingest_api._admin_body`, 64 KiB JSON) over `instrument_admin.py` (the operations, tested in-process: create/edit with `live_since` clock-skew warnings, export path/adopt through `exports.HubExporter` with its refusal reasons as 409s, per-instrument calibration CDF/assignments → `pipeline.on_calibration_saved` in the same txn, the corrections editor → `store.corrections.set_all` + queueing `pending_corrections` in one txn, gc1's one-time seed from the phase-1 file, methods seen/map → `pipeline.on_method_mapped`, backfill release, conflicts Keep/Replace) and `standards.py` (D12: comparison standards tagged by instrument; existing files migrate to gc1 once). Rows are served without `token_hash`. The page (`templates/instruments.html`, `static/js/instruments.js`) builds its DOM with `textContent` only (agent strings are untrusted, M5); `/calibration?instrument=<id>` edits any instrument (default gc1). `instruments.startup` defaults the Worker to `instruments.corrections_provider(db)` (gc1's phase-1 file until seeded); the hub overrides it with the store-only provider, seeds gc1 automatically at the first start (retried by Maintenance; the admin seed then answers 409), and other instruments stay `pending_corrections` until their 11 values are entered. Plan and carry-overs: `docs/superpowers/plans/2026-09-28-phase2-2A2-instruments.md`.
- **QBench API credentials** — `qbench_secrets.py` resolves the client id/secret at use time (`QBENCH_CLIENT_ID`/`QBENCH_CLIENT_SECRET` env → the JSON store at `QBENCH_STORE_PATH` or `%APPDATA%\ASAPLabs\qbench.json` → `QBenchSecretMissing`); `qbench_client.py` no longer reads them at import, so the app boots without them. Settings > QBench API (`GET/POST /api/qbench-api-credentials`, admin-gated) test-authenticates a submitted pair with one bounded token request and only then writes it with `qbench_secrets.save_default()` (atomic, keeps other `profiles`). The secret is never returned. This is separate from the Selenium web login (`/api/qbench-credentials`, `qbenchlogin.txt`).
- **`paths.py`** — where every piece of runtime state lives, all under `GC_DATA_DIR` (see *Deployment*); without it `data_dir()` is `None` and every other function raises `DataDirMissing` (message points to DEPLOY.md). Stdlib-only, no import-time side effects, every function takes `env` for tests. Settings, notifications and the defaults in `settings.DEFAULTS` all come from here.
- **`version.py`** — `APP_VERSION` from the first line of `VERSION` next to the code, `"dev"` when absent. Shown in the bottom-right badge on every page and reported by `/healthz`.
- **`restart_policy.py`** — how the process may restart itself: always exit (the updater relaunches it); spawn a replacement only while the updater is `paused`, never while `switching`/`switch-accepted` exists; the once-a-day auto-restart storm guard and minimum uptimes; `decide()` / `await_switch()` for the restart→switch handshake. Stdlib + `restart_update` only, so it is unit-tested without importing app.
- **`instance.py`** — the port: `resolve_port` (`PORT` → `--port` → `GC_PORT` → 5560), validation and the port-in-use probe. Stdlib-only and side-effect-free at import.
- **`settings.py`** — the global settings, `GC_DATA_DIR/settings.json` (`paths.settings_file()`). `DEFAULTS` is the source of truth for keys; `load_settings()` merges the file over defaults and ensures the comparison-standards dir exists. Per-instrument configuration (calibration, corrections, export path) lives in the store's `instruments` rows; `settings.json`'s calibration keys only seed gc1 once. Importable without `GC_DATA_DIR` (tools, tests): `CONFIG_PATH` is then `None`.
- **`qbench_pdf_uploader.py`** — headless-Chrome Selenium upload of a PDF to a QBench sample. `attach_pdf_to_sample()` does: API lookup (lab_id → sample_id) → login (raising `LoginFailedError` on bad creds/lockout) → attach → save → verify. `app.py` catches `LoginFailedError`, so keep it.
- **`qbench_client.py`** — thin QBench REST v2 client (JWT auth, rate limiting, retries). **Must stay vendored in this repo.**
- **`analysis_core.py`** — Analysis-tab numerics, importable without app.py's side effects. Two deviation channels: the rolling low-quantile *trend* difference (broad envelope deviations) and a *spike* channel on the raw sample−standard difference with a min-width guard (`analysis_spike_min_width_min`, default 0.02 min) — the trend's low quantile erases short tall spikes (gasoline adulteration) by construction, so never remove the spike channel. Also owns `resolve_report_ranges` (request ranges → saved `analysis_range_overlays` → legacy gas/oil; an explicit `[]` means no ranges) and the phase 3 **range-driven bullets**: `range_windows` (the one carbon↔time conversion, linear extrapolation, clipped to `min(run end, x_max_min)`; the UI and PDF draw range boxes from these windows), `report_params` (operator params from the request, `analysis_min_width_min`/`merge_gap_min`/`spike_min_width_min`/`spike_report_threshold` from settings only), `build_deviation_report` → `render_bullets` (one bullet per deviating range plus one outside/“Across the run” line, never more than ranges + 1), `deviation_conclusion`, and `analyze_report` (both channels + bullets, what `app._report_content` calls). `generate_conclusion` (per-excursion) is kept only as the regression reference.
- **`sample_flags.py`** — operator-defined flag rules (JSON in `sample_flag_rules` setting): `{name, above|below, threshold, t_start, t_end, color, enabled}`. `above` = any point in window exceeds; `below` = all points stay under (no-signal case). Legacy `early_signal_*` settings auto-migrate. Results are cached per sample in the store's `sample_cache`, keyed on a rules fingerprint, filled off the request path (`app._schedule_cache_refresh`; `/api/files` never reads a CDF).
- **`fuel_fit.py`** — fuel-type best-fit vs the comparison standards: baseline-subtracted, area-normalized envelopes (amplitude-invariant), small retention-shift search, cosine score; NNLS blend names two-component mixes (`Mix: A + B (80/20)`), else `Mix`. Tunables in settings (`bestfit_*`). Called from `distill.compute` (columns `Best Fit`/`Fit Score`), the `/api/best-fit` route, and `sample_cache` (keyed on a best-fit config + standards fingerprint). CDF reading is injected (`load_standards(dir, reader)`) to avoid import cycles.
- **Main page** (`templates/index.html`, `static/js/app.js`): the samples list and results table, chromatogram traces, the Analysis tab, report export, reprocess (preview then confirm, by sample ID), Export to LIMS, the QBench upload queue, Settings and notifications. Samples are addressed by `sample_id`; non-final samples show why they are held. Operator actions (reprocess, Export to LIMS, QBench upload, restart) need no password, as in v1; only the cross-site guard protects them (a decision for a later release). Describe features here, not code positions: this file changes often.
- **Frontend pure-logic modules** (window globals + module.exports, node-tested via `node tests/js/run.js`): `selection.js`, `report_payload.js` (export/queue/QBench payloads carry the ranges — `[]` = none — and the captured trend parameters/thresholds/x-max, never bullets), `flagrules.js` (rule editor rows ↔ rules, legacy migration mirror), `restart.js` (Restart button label/confirm text from the staged-update decision), `qbench_api.js` (the QBench API credential status line), `instruments_logic.js` (the Instruments page: clock skew, agent health, correction inputs, installer outcomes).

## QBench gotcha (caused a production outage)

`qbench_pdf_uploader._api_lookup` does `from qbench_client import QBenchAPIClient`. It must resolve the **local** `qbench_client.py` (on `sys.path` because `app.py` is run from its own folder, with `cwd=current` by the updater). Do **not** reintroduce any `sys.path.insert` to an external share path (the old `…\COA Reviewer\V2\Past Data Manager\API`) — that dir is gone and importing from it took uploads down. `tests/test_qbench_import.py` guards this.
