    Load CDFs from a folder

    Submit every CDF in a server folder, oldest first. Running it again skips what is already in.

    Purge instrument data

    Remove one GC's samples, e.g. to redo an import. The database is backed up first; CDFs are moved, never deleted.

    What is kept, and how to restore

    Removed with the samples: results, export rows, comments, report records, conflicts and queued jobs. Kept: the instrument and its settings (calibration, corrections, methods, LEM machine, live since, results file, agent and token), the other instruments' data and the global settings. That instrument's processing and uploads pause while it runs; its agent retries.

    The whole database is first copied to backups\pre-purge-<instrument>-<time>.db (never pruned), and the purged CDFs move to purged\<instrument>-<time>\; a CDF still in use (a calibration, a comparison standard, a blank) stays. The results CSV LEM reads is not edited.

    Restore after a purge (DEPLOY.md): stop the hub, copy the pre-purge backup over gc.db, move the purged folder's contents back into the data folder, start the hub.

    Results files

    Each GC's results CSV, which LEM reads. A refused file is never written until it is adopted or moved.
