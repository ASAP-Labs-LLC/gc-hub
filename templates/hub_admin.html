Hub admin

Every action below needs the admin password (set once at /admin/setup). Back to the app

Load CDFs from a folder

One-shot and read-only on the folder: every *.CDF under it is submitted in injection-time order and processed by the hub. Re-running resumes (duplicates are skipped). Backfill samples are never exported until released.

Import v1 history

Import one instrument's v1 processed CDFs and results CSV (read-only on both). Every imported sample is backfill and is never exported automatically. A dry run only classifies; the real import runs as a job like the loader above (one job at a time), resumable, and can be stopped between batches.

Comment presets

The one-click comments on the Analysis tab. Their text is copied into a sample's comment when it is added (editing a preset later does not change existing comments), and comments print in reports that may reach customers: word them for a report. At most 50 active, 200 characters each. Deactivated presets are kept and can be reactivated.

    Exports

    Each instrument's results CSV (append-only; LEM tails it). A refused file is never written until it is adopted or the export is moved to another path. Never point LEM at a freshly written file without setting its tail offset to the end.

    Diagnostics

    Download one zip with what is needed to debug this hub: version and runtime state, logs, the store's tables, a copy of the database, export health, parity reports, calibration files, the updater's log and state, and the CDFs of samples that are held or in error. Secrets are left out or replaced by [REDACTED]: the admin password (and its hash), agent tokens, the setup code, the QBench API credentials, the QBench web login (qbenchlogin.txt on the share) and GitHub tokens. The hub keeps working while it builds; one bundle at a time.

    The database copy holds everything in the store, including soft-deleted comments and the operators' IP addresses (internal lab addresses), as well as sample IDs, results and CDFs. Treat the zip as lab data.

    To have Claude look at it: save the zip where Claude can read it (for example the Downloads folder of the computer you run Claude Code on, or a folder you give Claude access to), then tell Claude its path, e.g. "debug the GC hub from ~/Downloads/gc-diagnostics-….zip". Don't email it or post it anywhere public.
