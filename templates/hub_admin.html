    Results files

    Load CDFs from a folder

    Read-only on the folder: every *.CDF under it is submitted in injection-time order and processed by the hub. Running it again resumes (duplicates are skipped). Backfill samples are never exported until released.

    Import v1 history

    One instrument's v1 processed CDFs and results CSV (read-only on both). Every imported sample is backfill and is never exported automatically. A dry run only classifies; the real import is resumable and can be stopped between batches. One job at a time.

    Purge instrument data

    Removes one instrument's samples from the hub (all of them, or only its backfill samples, i.e. imported history, to redo an import) with everything that belongs to them: results, export rows, comments, report records, conflicts and queued jobs. The instrument itself and its settings stay (calibration, corrections, methods, LEM machine, live since, results file, agent and token), and so do the other instruments' data and the global settings. Processing and uploads for that instrument pause while it runs (its agent retries).

    First the whole database is copied to backups\pre-purge-<instrument>-<time>.db (never pruned). The purged samples' CDF files are moved, never deleted, to purged\<instrument>-<time>\ in the data folder; a CDF that something kept still uses (a calibration, a comparison standard, a blank a kept result subtracted) stays where it is. The results CSV LEM reads is not edited: rows already in it stay.

    Restore after a purge (DEPLOY.md): stop the hub, copy the pre-purge backup over gc.db, move the contents of the purged folder back into the data folder, start the hub.
